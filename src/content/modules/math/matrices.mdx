## A Matrix Eats a Vector

Start with what you already know. A matrix is, before anything else, a rectangular grid of
numbers — and you have met thousands: a spreadsheet of survey responses, rows for respondents
and columns for questions, is a matrix. So far, a matrix is a <em>noun</em>: a container that
holds data. This module is about its other life, as a <em>verb</em>.

Here is the mechanical recipe, the one taught in school. To multiply a matrix by a vector,

Read what that says. The matrix spends the input's first coordinate on its first column and

## Two Ways to Read Ax

The row-wise recipe and the column-wise regrouping are not just two ways to compute — they
are two ways to <em>think</em>, and downstream mechanisms need both fluently.

<div class="formula-block">
  <Tex tex={math.rowRead} />
  <Tex class="formula-block__caption" tex={math.rowReadCaption} />
</div>

<strong>The row view</strong> says: each output entry is a dot product — an M1-style
similarity measurement — between one row and the input. When a transformer scores one query
against every key at once, that is a matrix–vector product read row-wise: each row of the
key matrix interrogates the same query.

<strong>The column view</strong> says: the output is a mixture of the columns, weighted by
the input's entries. When the input is one-hot — a single 1, everything else 0 — the
"mixture" selects exactly one column. That is an embedding lookup: a word's index, encoded as
a one-hot vector, multiplied into an embedding matrix, returns that word's vector. Lookup and
matrix multiply are the same operation — which is not a curiosity; it is why the lookup is
differentiable and why embeddings can be <em>learned</em>.

## Composition, and Why Matmul Looks the Way It Does

Functions compose: do one, then another. Apply <em>A</em> to a vector, then apply <em>B</em>
to the result. The natural question — is there a single matrix that does both in one step? —
has a yes, and demanding it <em>forces</em> the definition of matrix multiplication:

<div class="formula-block">
  <Tex tex={math.entryRule} />
  <Tex class="formula-block__caption" tex={math.entryRuleCaption} />
</div>

Two consequences worth internalising. First, <strong>order matters</strong> — and once you
think in transformations, this is obvious rather than mysterious. Stretch-then-rotate and
rotate-then-stretch land shapes in visibly different places (the problem set has you compute
one such pair; replay it in the widget with the Scale and Rotate presets). "Matrix
multiplication is not commutative" stops being an algebra fact to memorise and becomes a
statement about the world: doing things in a different order does different things.

Second, this is <strong>what a deep network is</strong>. Layer after layer applies a
transformation to the previous layer's output — composition, dozens deep. The reason "it's
matrix multiplication all the way down" is a meaningful sentence about transformers is that
matrix multiplication <em>is</em> composition of functions, and composition is how simple
functions become expressive ones.

## Shapes as a Type System

The most practically useful section in this module, and a skill rather than a fact. Every
matrix expression has a shape signature:

<div class="formula-block">
  <Tex tex={math.shapesRule} />
  <Tex class="formula-block__caption" tex={math.shapesRuleCaption} />
</div>

Treat shapes the way a programmer treats types. Before evaluating any product, read the
signature: do the inner dimensions match? What survives? An expression that type-checks may
still be the <em>wrong</em> computation — but an expression that fails the check is certainly
broken, and the check costs seconds. Shape errors are the single most common failure in this
curriculum's practical notebooks, and nearly all of them are caught by this discipline
applied before running anything.

Two habits complete the skill. First, real data adds a <strong>batch dimension</strong>:
frameworks process many inputs at once, so a batch of 32 vectors of dimension 768 is a
32 × 768 matrix, and the convention is that batch comes first. When you meet a
three-dimensional array — batch × sequence-length × dimension, the standard shape of a
transformer's hidden states — the same annihilation rule applies to the trailing two
dimensions while batch rides along. Second, <strong>read shape errors as information</strong>,
not as failure: the message names two shapes, and the mismatched inner pair tells you which
object is oriented wrongly or which dimension you forgot — usually pinpointing the bug to a
single missing transpose. The companion notebook drills exactly this, on deliberately broken
code.

## A Bestiary of Special Matrices

A few families of matrices come up so often that recognising them by <em>behaviour</em> —
not by the pattern of their entries — is a working skill. Each is introduced here by what it
does; reproduce each one in the widget above as you read.

<strong>The identity</strong> does nothing: every basis vector goes to itself, so every
column is a basis vector. It is the "multiply by 1" of the matrix world, and the benchmark
every other matrix is compared against.

<strong>Diagonal matrices</strong> scale each axis independently — the Scale preset: ê₁
stretched, ê₂ squashed, no mixing between axes. Cheap to apply, trivial to reason about,
and the shape every matrix "wants" to be — M4's whole story is that an arbitrary matrix is
rotations wrapped around a diagonal core.

<strong>Orthogonal matrices</strong> rotate or reflect:

<div class="definition-box">
  <p class="definition-box__label">Definition</p>
  <p class="definition-box__term">Orthogonal Matrix</p>
  <Tex tex={math.orthDef} />
</div>

The Rotate preset is one kind; the Reflect preset is the other (its determinant is
&minus;1 — area preserved, orientation flipped). Orthogonal maps are the <em>safe</em>
transformations: they move information around without amplifying, shrinking, or destroying
any of it, which is why they appear wherever a computation must not distort similarity —
problem 5 connects this to how modern transformers encode word positions.

<strong>Symmetric matrices</strong> (equal to their own transpose) get one sentence now and a
module later: they are exactly the matrices whose action is a pure scale along some rotated
set of axes, and M4 is the payoff of that fact.

Read it with this module's eyes. <em>W</em> is a transformation — it rotates, stretches,
shears, and projects its input; its row view says each output entry measures the input
against a learned pattern, and its column view says the output mixes learned directions.
The bias <strong>b</strong> is a shift — the one move a linear map cannot make is moving the
origin, and <strong>b</strong> restores that freedom. An embedding layer is the column view
with one-hot inputs. An attention-score computation is the row view at scale. A transformer
stacks a few dozen of these, composed in the precise sense of this module's third section —
with nonlinearities between layers, because a composition of purely linear maps collapses
back into one linear map, a fact the deep-learning track opens by demonstrating.

And the planted debt: this module kept saying "M4 pays this off" — the Collapse preset, the
diagonal core, the symmetric preview. That module takes matrices <em>apart</em>, and it is
where low-rank adaptation — the fine-tuning method the LLMs track teaches — becomes
inevitable rather than clever.

  <h2 id="module-summary">Module Summary</h2>
  <p>
    A matrix is a function that takes vectors to vectors, and its columns are the images of
    the basis vectors — a handful of arrows that determine the entire map, because linearity
    fills in everything between them. Matrix–vector multiplication reads two ways: rows as
    similarity measurements (the attention picture) and columns as weighted mixtures (the
    embedding-lookup picture). Matrix multiplication is function composition — its entry rule
    forced rather than chosen, its non-commutativity the everyday fact that action order
    matters. Shapes form a type system: inner dimensions annihilate, outer survive, batch in
    front, and a shape error names the exact dimension you got wrong. The special matrices
    are known by behaviour — identity, diagonal scaling, orthogonal rotation preserving every
    dot product, symmetric as M4's opening act. And the linear layer <em>Wx + b</em> — a
    transformation plus a shift — is the atom out of which every network in this curriculum
    is composed. The planted debt: what the Collapse preset showed, a matrix crushing
    dimensions, becomes quantitative in M4, where low rank turns from a failure mode into the
    most useful fact about large matrices.
  </p>
